# ADR-004: 개발 사이클과 AI 하네스

- 상태: 채택
- 날짜: 2026-11-10

## 결정
- 8단계 개발 사이클(스펙 → 태스크 → 구현 → 유닛 테스트 → 수치 검증 → 사람의 의미 리뷰 → 통합 테스트 → 분리된 리뷰)을 따른다.
- 이 방식은 TDD 가 아니다. 구현 후 테스트를 채우는 방식이며, 테스트가 스펙과 어긋나는 위험은 6단계 사람 리뷰와 "발견 사항 보고" 규칙으로 막는다.
- 커버리지 기준: `domain`, `application/service`, `adapter/in/web` LINE·BRANCH 100%. `./gradlew build` 가 강제한다.
- 배포를 하지 않으므로 push Hook 과 CI·SonarQube 는 두지 않는다.

## 근거
미리디 블로그 「AI Agent로 테스트 커버리지 100% 달성한 실전 전략」(2026-04)의 하네스 원칙: 절차 고정, 수치 기반 보고, 측정과 작성의 역할 분리, 태스크 단위 분할.
